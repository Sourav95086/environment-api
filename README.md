# Environmental BRSR Report Agent

A starter Python + LangGraph project for generating a **draft environmental section** of an ESG/BRSR report from project documents stored in Supabase Storage.

> The current pilot data is synthetic and is not actual MEIL data. Generated reports must be treated as drafts until reviewed by authorized personnel.

## Workflow

1. Receive a numeric `project_id` from `public.project_details`.
2. Read `project_details` and `project_environmental_files`.
3. Download the referenced PDF objects from the private Supabase Storage bucket (`bput` by default).
4. Extract PDF text.
5. Ask the configured LLM to structure the extracted information as JSON, keeping unknown/missing data explicit.
6. Run basic deterministic consistency checks.
7. Generate a PDF draft with data gaps and source document references.

## Setup (Windows PowerShell)

Create a separate directory for this project, extract this ZIP into it, and open a terminal in that directory.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Fill `.env` with your actual Supabase URL, Supabase service-role key, and Groq API key.

**Never commit `.env` or expose your service-role key.** The service-role key bypasses Storage/database RLS and must remain backend-only. Use only a trusted machine.

## Find the project ID

Run in Supabase SQL Editor:

```sql
SELECT project_id, project_name
FROM public.project_details
ORDER BY project_id DESC;
```

Use the numeric `project_id` from this result. `SYN-ENV-001` is a Storage folder label, not the numeric database ID.

## Run the agent

```powershell
python app.py --project-id 1
```

Replace `1` with the actual numeric project ID. Outputs are saved under `generated_reports/` as JSON and PDF.

The default model is configurable through `GROQ_MODEL`. If that model is not available in your Groq account, set it to a currently supported model.

## Important implementation notes

- The agent uses Storage object paths stored in the database, not stored signed URLs. It downloads directly through the Supabase Storage SDK, which works with a private bucket.
- `project_details_file` and the six environmental columns must contain paths relative to the configured bucket, e.g. `SYN-ENV-001/02_energy_records.pdf`.
- The README/data dictionary file is not mapped to the two project tables and is not fetched by this initial workflow.
- This first version processes text-based PDFs. Scanned/image-only PDFs need OCR, which is not included yet.
- Calculations are not treated as verified if source data or calculation factors are incomplete. The LLM output is a draft, not legal assurance.
- The report labels the output as a draft and flags missing/unknown data. Have a qualified reviewer validate BRSR mapping and applicability before any formal filing.


## REST API: generate report and upload PDF

The API uses the same LangGraph workflow as the CLI. It generates the JSON/PDF,
uploads the PDF to the configured Supabase Storage bucket, and returns the report
JSON plus a signed download URL.

Install dependencies:

```powershell
pip install -r requirements.txt
```

Run the API from the project directory:

```powershell
uvicorn api:app --host 0.0.0.0 --port 8000
```

Open interactive API docs at `http://127.0.0.1:8000/docs`.

Health check:

```http
GET /health
```

Generate a report:

```http
POST /api/reports/1
```

Example response shape:

```json
{
  "success": true,
  "project_id": 1,
  "report": {
    "project_id": 1,
    "project_name": "Example project",
    "reporting_period": "FY 2026-27"
  },
  "pdf_url": "https://your-project.supabase.co/storage/v1/object/sign/bput/generated-reports/...",
  "storage_path": "generated-reports/project-1/environmental-report-....pdf",
  "pdf_url_expires_in_seconds": 604800
}
```

The actual `report` object contains all fields generated by your current report schema;
the abbreviated JSON above is only an example. The PDF URL is signed and temporary.
Set `SIGNED_URL_SECONDS` in `.env` to control its lifetime. Keep the Supabase service
role key on the server only; never put it in Android/web clients.

For deployment, use a production ASGI server and protect the endpoint with your
organization's authentication/authorization before exposing it publicly.
